# M88派生版を参考にしたディスク修正

## 参照元

- [M88M aee8d0061852e2b737d7456e2bd9570e584e81b1](https://github.com/bubio/M88M/commit/aee8d0061852e2b737d7456e2bd9570e584e81b1)
  のトラック書き戻し失敗処理、ロック位置、フォーマット対象ドライブの修正。
- [GIMONS氏のM88g 20250513](http://retropc.net/gimons/emulators/#m88g)
  の公開ソース `src/pc88/fdu.cpp`。D88の診断読み出しデータ生成を比較した。

既存M88コアの著作権表記・利用条件を維持し、確認できた箇所のみ個別に修正する。
FDX対応やFDC全体の置き換えは含まない。

## 修正内容

- `DiskManager::UpdateDrive` は、シークとトラック書き込みの成功後に変更済みフラグを解除する。
  失敗時は変更を保持し、後のUpdateまたはUnmountで再保存する。
  holder/sizechangedの確認もロック取得後に行う。
- `FormatDisk(1)` の変更済み・サイズ変更フラグをドライブ2に設定する。
  従来はドライブ1を指しており、ドライブ2のフォーマットが保存されなかった。
- `FDU::MakeDiagData` のデータアドレスマークを通常 `FB`、削除済み `F8` にする。
  FMでMFMセクタを読む際のポインタ移動量をゼロ埋め長と一致させ、後続セクタの位置ずれを解消する。

## 検証

`disk_regression_test` はROMや市販ディスクを使わず、合成D88とFDUを使用する。

- 実際の背後ファイルを読み取り専用／閉じた状態にして、書き込み／シーク失敗を発生させる。
  復旧後のUpdateとUnmountそれぞれで保存し、再マウント後のセクタ内容を検証する。
- 失敗が継続する場合にUnmountが失敗を返すことを確認する。
- ドライブ2をフォーマットし、再マウント後の先頭・最終セクタを確認する。
  同時にドライブ1のファイル内容が変わらないことを確認する。
- FM/MFM、通常/削除済み、混在密度の有無の8通りで診断データのマーク・位置・内容を確認する。

修正前は20項目が失敗、修正後は全項目成功。GUI・ヘッドレスをビルドし、全23 CTestが成功した。

## 残る制限

Unmount自体が保存に失敗した場合にメディアを保持する改善や、ホストOSの遅延書き込み失敗までの
検出は含まない。RAM初期パターン変更も対象外。

## 続件: マウント前検証と読み取り専用判定

同じM88Mの修正を参考に、既存ファイルのマウント前検証を共有DiskManagerに追加した。
存在しないファイル、不正なヘッダー、未対応メディア、範囲外のディスク番号、
実体のないプレイリスト項目では、現在のドライブや未保存のセクタを維持する。
新規ファイル作成は従来の経路を使い、事前検証ではファイルを作成・切り詰めしない。
これは完全なトランザクションではなく、検証後の外部ファイル変更やメモリ確保失敗までは保護しない。

FileIOが読み取り専用にフォールバックした場合も、プレイリストかどうかに関係なく
ゲストに書き込み禁止を返す。DiskImageHolderの未初期化メンバーも初期化し、
Connectは開いているholderだけを再利用する。

追加テストでは上記5種類の失敗後に元のセクタともう一方のドライブを確認し、
正常な交換・同じイメージの再マウントも確認した。
Windowsの実際の読み取り専用属性を使い、書き込み禁止ステータス・ゲスト書き込み拒否・
ファイル内容の保持を確認した。追加テストは修正前13項目失敗、修正後成功。
GUI・ヘッドレスのビルドと全23 CTestが成功した。

## 続件: FDCのエラー通知とフォーマット中断

M88gのFDC/FDUと、[NEC µPD765A/B資料の転載](https://cpctech.cpcwiki.de/docs/upd765a/necfdc.htm)
のRead Data、Format、ステータス定義を照合した。M88g全体の移植ではない。

- ID CRCエラーをRead IDで通知し、Read/Write DataでもDEを維持して終了する。
  データCRCエラーのDE+DDとは区別する。
- データアドレスマーク欠落をMA+MDで通知し、存在するかのようにペイロードを転送しない。
- FormatのSC=0でバッファ所有ポインタを書き換える処理を除去する。
  M88gと同じくAT+ENで安全に拒否し、既存メディアを保持する。
  SC=0のこのステータスは互換実装としての防御的な選択であり、全実機の挙動を保証するものではない。
- Format中にTCを受けた場合、転送要求IRQとRQMを取り下げて完了処理を待つ。
  受信済みの完全な4バイトIDだけを使う既存動作を維持する。

`fdc_error_test` は合成D88をマウントし、実FDCのコマンド/データレジスタ、
スケジューラとIRQを通して検証する。FM/MFM、待ち時間ON/OFF、正常/ID CRC/データCRC/欠落マーク、
Write DataのID CRC、Formatの受信バイト数0/1/3/4/5/7/8/11/12とSC=0を確認する。
中断後のセクタ・埋め込みデータ、後続コマンドの実行、不要イベントが残らないことも確認する。
Format結果のCHRNは仕様表で意味を持たないため、特定の値を合格条件にはしない。

修正前の最終テストは46項目失敗、修正後は全項目成功。GUI・ヘッドレスのビルドと全24 CTestが成功した。
SC=0による不正ポインタ解放でテストプロセスが終了しないよう、
失敗を記録した後、テスト専用アクセスで解放時のポインタだけを元に戻している。
部分IDの物理的な書き込み跡、回転位置、オーバーランなどの精密なタイミング再現は対象外。
