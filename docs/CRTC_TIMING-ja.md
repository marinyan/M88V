# CRTC最終文字行の待ち時間

## 最終行の修正（PR #7）

Defender80側が報告した「最終文字行の待ちが抜ける疑い」を調査し、
CRTCのイベント進行と `GetFramePeriod()` の不一致を確認した。

`StartDisplay()` は表示開始時刻に先頭行を取得する。
修正前は最終行を取得した直後に `ExpandLineEnd()` を呼んでいたため、
表示期間が `linetime * (height - 1)` となっていた。
特殊制御コードで残り行の取得を省略する場合も、現在行の時間が抜けていた。

修正後は最終行の取得から1文字行分待ってVRTCを立ち上げる。
途中打ち切りの場合は現在行と残り行の時間を合わせて待つ。
帰線期間の長さ、行ごとのDMA取得時刻、画面データは変更しない。
終了待ちの状態は既存の `event > 1`（待ち行数+1）として保存する。

| 条件 | 修正前の周期 | 修正後の周期 |
| --- | ---: | ---: |
| 25文字行、帰線7行、1行50 tick | 1,550 tick | 1,600 tick |

1 tickは10μsなので、この設定では15.5msから16msへ変わる。
これは `GetFramePeriod()` が返す周期への整合であり、実機の正確な走査周期や
60Hzへの補正を行ったものではない。行時間の整数丸めも今回の変更対象外。
VRTC同期で動くゲームの更新頻度に影響するため、以前のFPS測定値とは区別する。

回帰テストはROMを使わず、CRTCをI/O経由で設定してスケジューラを進め、
VRTC通知の時刻を測定する。

## 由来

M88V固有でもM88Mで導入されたものでもなく、原版M88から継承された処理。
少なくとも原作者配布の2.17まで同じ不足を確認できる。
それ以前の最初の導入版は今回の調査では特定していない。

| 確認対象 | 根拠 |
| --- | --- |
| 原版M88 2.17 | [原作者配布アーカイブ](http://www.retropc.net/cisc/m88/dl/M88_217s.tar.bz2) の `M88p2/src/pc88/crtc.cpp`、508–528行。通常の最終行で即座に終了し、途中打ち切りも `linetime * e`。 |
| 原版M88 2.21a取り込み | [2012-09-11の原版取り込みコミット](https://github.com/rururutan/m88/commit/22f656b27cc3229934218df4b8336fd27e739d99) の [CRTC](https://github.com/rururutan/m88/blob/22f656b27cc3229934218df4b8336fd27e739d99/src/pc88/crtc.cpp#L509) に同じ処理。 |
| M88M | [固定コミットのCRTC](https://github.com/bubio/M88M/blob/2c40070874b75a10cd55b208bea13883f65f2f46/src/pc88/crtc.cpp#L521) に同じ処理。 |
| M88V | 初回取り込み `624fd0e` から同じ処理を継承。 |

## 検証結果

- 修正前: 20文字行・1行80 tickで、表示期間が期待1,600 tickに対し1,520 tickとなり再現。
- 修正後: `crtc_timing_test` の40ケース成功。20/25行、15/24kHz設定、DMA停止・不足、
  最初／途中／最後の行での表示打ち切り、間引き、1行境界、終了待ち中の保存・復元を含む。
- GUI・ヘッドレスをビルドし、全16 CTest成功。
- 実ROMのN・N88V1・N88V1H・N88V2で、チェックポイント復元、継続実行、入力リプレイ、
  破損ファイル拒否、別プロセスへの状態復元が成功。

## M88amを参考にした追加の精度改善

[M88am 2026/09-01公式配布](https://www.ambientworks.jp/_site/download/M88am-202609-01.zip)
の `CHANGES.md` §2.4 と同梱 `crtc.cpp` / `base.cpp` を比較し、
以下の方式をM88Vのコアとチェックポイントに合わせて実装した。
参考元の追加コードはambientworks.jp / @sobamixのBSD 2-Clause License。
著作権表記を `LICENSE` に追加している。

- **CRTCの端数保持:** 走査線時間6.258 / 4.028 tickを1/65536 tick精度で保持し、
  イベントを予約する際に整数化した残りを次へ繰り越す。
  24kHz・16走査線/文字の64.448 tickを毎行64 tickへ切り捨てる誤差をなくす。
- **CRTCの予定時刻保持:** 実行したCPU命令がイベント期限を超えても、次の予約は
  元の予定時刻を基準にする。各行での遅れを累積しない。
  1イベント分以上遅れた場合は現在時刻から再開して集中発火を避ける。
- **600Hzタイマー:** 167 tick固定（約598.802Hz）を、166/167/167 tickの周期へ変更。
  M88amの端数繰り越し方式を参考に、こちらは100000/600の整数商・余りを使い、
  100秒で60000回になる。1回ごとの時刻は10μs単位に量子化される。
- **保存・復元:** 精密チェックポイントに端数と予定時刻を保存する。
  旧式CRTC状態の帰線待ち値FFHも正しく復元する。

先の表の1600 tickは最終行だけを修正した時点の値。
追加改善後、25行・帰線7行・8走査線/文字・15kHz設定では平均1602.047 tick、
25行・帰線3行・16走査線/文字・24kHz設定では平均1804.544 tickとなる。
`GetFramePeriod()` はこの平均値の整数部を返すが、CRTCイベント自体は端数を持ち越す。
元の走査線時間定数を高精度に扱う変更であり、実機での計測結果を保証するものではない。

**互換性:** 精密チェックポイントの形式を2へ更新した。
旧形式1の `.m88vstate` とそれを含む入力リプレイは読み込めないため、作り直す。
不一致は現在のマシン状態を書き換える前に拒否する。
旧式デバイス状態のレイアウトは維持し、そちらの復元では端数位相をゼロから再開する。

追加テストではCRTCの1000フレームとCPU実行超過、600Hzの100秒・60000割り込みを検証する。

実ROMで計測ON/OFFの同一性を確認した際、`ADD HL,rr` が保持すべきS/Z/PVの
遅延評価を捨てる既存のCPU不具合も再現した。これはM88amの `CHANGES.md` §2.1 #8にも
記載されている。16bit加算で作業変数を更新する前に保持フラグを確定させ、
デバッグ計測の有無で実行結果が変わらないように修正した。
