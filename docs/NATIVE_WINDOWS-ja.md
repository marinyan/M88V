# Windows GUIの土台

Windowsの標準GUIはrururutan/m88の従来Win32版です。
基準は`1c48d83070202eef43ab00db757131d0cc4768cc`（2020-12-17）。
リポジトリ全体を昔の状態へ戻したり、Git履歴をリベースしたものではありません。
既存のWin32ソースを正式にビルド対象へ戻し、M88Vの共通コアへ接続しています。

- `m88_win32` → 従来メニュー・ディスク・テープ操作／録音保存・キーボード・描画・音声。
- `m88_raylib` → 任意のポータブルGUI。Windowsでは別名`m88v-raylib.exe`。
- `m88_headless` → 既存の開発用HTTP API、計測、メモリマップ、ウォッチ、履歴、記録・再生。
- 3つとも同じ`m88core`・`m88_development`をリンクします。GUIだけ古いx86 CPUへ戻しません。

53Hのリセット時初期化とC++ Z80のVRAMウェイト修正は維持しています。
計測結果はCPUのエミュレート時間であり、実機そのものの測定値ではありません。

## ビルド

```powershell
.\scripts\build_gui.ps1
# 任意のraylib版。標準配布EXEを上書きしない別名。
.\scripts\build_gui.ps1 -Frontend raylib
```

Win32版は`dist/windows-x64/m88v.exe`です。`-NoPublish`はビルドのみ行います。
`M88V_GUI_FRONTEND=win32|raylib`でCMakeからも切り替えられます。
旧Visual Studio 2008プロジェクトではなく、CMakeと現在のWindows SDKを使ってください。

MSVC/Ninjaでは`/showIncludes`の言語と依存追跡の接頭辞を一致させています。
日本語版コンパイラだけがある場合も英語リソースを前提にしません。
`scripts/test_msvc_dependencies.ps1 -BuildDirectory build/gui-win32-msvc`で確認できます。
新しいソースを追加した場合は、ビルドスクリプトを再実行してCMakeを再構成してください。

## 設定とROM

設定はEXEと同じ場所の`m88v.ini`へ保存します。INIのセクション名は旧形式互換の
`[M88p2 for Windows]`です。別名のEXEを作った場合はそのファイル名のINIになります。
旧M88のINIやraylib版のバイナリ設定を自動移行・変更する処理はありません。

ROM参照先の優先順位は次のとおりです。

1. `M88V_ROM_DIR`、未設定または空なら`M88M_ROM_DIR`。
2. INIの`BIOSPath`。
3. EXEと同じフォルダの`roms`、なければ`rom`。
4. EXEと同じフォルダ（`N88.ROM`または`PC88.ROM`がある場合）。
5. `%APPDATA%/M88M/roms`。

明示指定した参照先の不足はエラーとし、別のROMセットへ黙って切り替えません。
N80 ROMの別名処理は共通の一時オーバーレイを使い、元ROMを書き換えません。
通常起動の既定はN88V2。ゲーム開発用スクリプトでは従来どおり機種を明示できます。

## テープと開発用起動

画面下部には、ディスク 1／2 とカセットの名前・状態・アクセスランプを表示する
[メディア状態バー（試作）](MEDIA_STATUS-ja.md) を追加しています。

`Tape → Open`でT88を開き、対象に合った`CLOAD`／`MON`等を入力します。
T88のドラッグ＆ドロップも従来のテープ処理へ渡します。開くだけで実行は始まりません。
再生テープと録音バッファは独立しています。CMT 出力は `Tape → Save recording as` から
明示的に保存します。空 T88 の作成・巻き戻しなどの手順は [テープ操作](TAPE-ja.md) を参照してください。

`start_gui_game.ps1`と`M88V_LOAD_BIN`／`M88V_LOAD_ADDRESS`を引き継いでいます。
BIN は物理 RAM へ置き、サイズに応じて EFF0H または FFF0H のランチャから開始します。
ロード前に CPU を走らせません。配置とスタックの条件は [BIN 直接ロード](HEADLESS_API-ja.md#bin直接ロード) を参照してください。
Win32版とraylib版のBINローダ実装は共通です。

## 画面の拡大・縮小

`Display → Scale` で 50〜400% を 50% 刻みで選べます。100% は 640×400、50% は 320×200 です。
`Display → Interpolation` では Nearest neighbor（ニアレストネイバー）、Bilinear（バイリニア）、
Bicubic（バイキュービック）を選べます。既定はバイキュービックです。保存済みの選択は引き続き使います。

ウィンドウの端や角をドラッグすると、50%刻みに制限されず自由なサイズに変更できます。
幅と高さは元画面の比率 8:5 に連動します。最小サイズは画面部分が 320×200 になる大きさです。
最大化時も 8:5 を維持して収め、余る領域は黒い余白にします。

下部のメディア状態バーとステータス欄は画面の外側に置き、拡大率の対象には含めません。
小さなウィンドウではメディアの状態文字を省略しますが、名前・アクセスランプ・クリック操作は使えます。
通常ウィンドウの幅と補間方式は `m88v.ini` の `[Display]` セクションに保存します。

拡大縮小は Win32 のウィンドウ表示が対象です。従来の全画面モードでは倍率・補間メニューを無効にし、
ウィンドウ表示に戻ると選択した設定を使います。raylib 版の表示は変更していません。
エミュレータ内部のフレームバッファと画面キャプチャは引き続き 640×400 です。

## 入力とフレーム待機の低遅延化

Win32版はキーイベントを受け取った時点で入力状態を更新します。エミュレーション側が
毎フレームUIの応答を最大10ms待つ処理をなくし、次のキーポート読み取りに反映します。
フォーカスを失うとキー状態を解除します。

フレーム待機には期限を指定した待機可能タイマーを使います。対応するWindowsでは高分解能
タイマーを使い、非対応なら通常のタイマーに戻ります。停止・再開・終了はイベントで通知し、
停止中の20msごとのポーリングもなくしました。時刻は64bitのQPCから換算します。
CPUはフレーム単位で実行し、命令の超過実行分を次のフレームへ繰り越します。
描画は従来と同じ実行フレーム単位で行います。一時的な遅れには追いつき実行し、
過負荷時には描画を間引きます。20フレームを超える遅れでは待機基準を現在時刻に合わせ直します。

拡大表示では、画面に変更がないフレームの変換・描画を省略します。通常は変更領域だけを
RGBに変換し、パレット変更や再表示要求では全画面を更新します。
等倍・ニアレストはDIBを直接転送し、バイリニア・バイキュービックの拡大縮小は
再利用するメモリ上で補間してから転送します。
バイキュービックはCatmull–Rom補間を使います。縮小時は補間範囲を広げて折り返し模様を抑えます。

`native_timing_test` は待機期限の誤差、`native_keyboard_test` はUIキューを処理しない場合の
入力処理時間を出力します。数値は実行環境の負荷で変動し、キー押下から画面表示までの遅延を
測ったものではありません。音声バッファの設定は変更していません。

ROMを用意した環境では `native_rom_timing_test.exe <ROMディレクトリ> [4|8]` で、非表示ウィンドウを
使ってWin32の入力・描画・実行タイマーを組み合わせた検証もできます。N88V1HのBASIC起動、
停止中のCPU停止、再開、3種類の補間、終了応答を確認します。ROMを必要とするため通常の
CTestには登録していません。音声デバイスは使用しません。

`native_input_latency_bench.exe <ROMディレクトリ> <出力CSV> [測定回数] [4|8] [補間0〜2] [倍率%]` は、
N88V1HのBASICへAキーを注入して、その文字の描画処理が完了するまでを測ります。
補間は0=ニアレスト、1=バイリニア、2=バイキュービックで、省略時は2・100%です。
CPU実行速度、描画間隔、描画処理時間も記録します。非表示ウィンドウでのソフトウェア経路の測定であり、
物理キーボード、DWM、モニター、音声の遅延は含みません。
基本条件の等倍で測った4MHz・8MHzの変更前後の数値と制約は[遅延測定記録](LATENCY_MEASUREMENT-ja.md)を参照してください。

## SHIFTとテンキー

NumLockによるSHIFTの偽の解放通知を除外するため、SHIFTはRaw Inputの実キーから取得します。
左右SHIFTのどちらでもテンキーとの同時押しが可能です。その他のキーとメニュー操作は
従来のWindowsメッセージを使用し、Raw Input登録に失敗した場合は従来入力に戻ります。

## 状態保存

ディスク未マウント・テープを閉じた開発セッションでは、録音バッファを消去し CMT 送信を停止してから、従来の状態保存メニューから
M88Vの検証付きチェックポイント形式を使います。Win32キーボード状態も保持します。
異なるGUI／headlessのチェックポイントは入力状態の形式が違うため相互ロードしません。
音声出力キュー・音源位相のサンプル単位の一致は対象外です。

メディアがある場合は従来のスナップショット経路を使用します。外部ディスク・テープの
書き込み自体を巻き戻す機能ではありません。開発APIの詳細は既存ドキュメントを参照してください。
