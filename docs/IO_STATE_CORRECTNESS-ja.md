# ブロックI/Oと状態復元の検証

## 対象

- Z80のINI/IND/OUTI/OUTDと反復命令INIR/INDR/OTIR/OTDR。
  反復中は21 T、最終転送は16 Tとし、転送と定義済みフラグを検証する。
  Zilog NMOSの非公式フラグ処理は、NEC製CPUでの一致を確認できていないため導入しない。
- Windowsフロントエンドの旧M88形式の状態読み込み。
  不正な入力を設定変更・リセット前に検出する。
- 精密チェックポイントでのADPCMの再生位置・デコーダ・読出し状態。
  保存後の継続と復元後の継続を比較する。

命令時間の参照資料は [Zilog Z80 CPU User Manual](https://www.zilog.com/docs/z80/um0080.pdf)と
[NEC 1979 Microcomputer Catalog](http://bitsavers.org/components/nec/_dataBooks/1979_NEC_Microcomputer_Catalog.pdf)
の印刷178・180・182ページ。NECのOTIR/OTDR表には反復21／終了16 Tが明記される。
INIR/INDR表は21 Tのみの記載で、終了16 TはZilog資料も併用して確認している。
NEC製CPUとの差を区別し、資料や実機の裏付けがない非公式動作をPC-8801全機種の仕様とは扱わない。

## 状態形式

精密チェックポイントはADPCMの内部状態を追加した形式3へ更新する。
形式1・2の `.m88vstate` と、それらを含む `.m88replay` は再作成が必要。
旧M88形式の状態ファイルとは別の形式であり、旧M88形式の対応を削除する変更ではない。

ホストの音声出力キューやFM波形全体の位相まで復元する変更ではない。

## 再現と検証

- ブロックI/Oは修正前に反復時16 Tとなる失敗を確認。修正後は98,312ケースで
  命令時間、PC、転送値、レジスタ、定義済みC/Z/N、監視実行との一致を確認。
  CPU本体の変更は4つの反復分岐への5 T追加のみ。非公式フラグとI/O順序は変更しない。
- ADPCMは実際のSnapshot保存・復元経由で、修正前の波形/EOS不一致を再現。
  修正後は8kHz／44.1kHz、単発／反復、1bit／8bitメモリ、再生途中／終端後、
  RAM読出しパイプラインの継続を検証。音声とEOSの発生も確認し、無音だけで成功しないようにしている。
- 旧形式はDeviceListの「後方デバイスの版不一致で失敗しても前方デバイスが変更済み」を再現。
  GUIと共有する事前検査に対し、通常／圧縮ファイルの全位置での切断、長さ・設定・レコードの異常を検証。
  合成ROMを使った実コアでも音源構成・拡張RAMの異なる状態を検証する。
  GUIのダイアログ操作を自動化した検証ではない。
- 全22 CTest成功。実ROMのN／N88V1／N88V1H／N88V2で保存・復元・継続・リプレイ・
  旧形式拒否・破損拒否・別プロセス復元が成功。4MHz／8MHzの起動・描画も確認。

## 旧M88形式の範囲

設定変更・リセットの前に、ヘッダー、展開サイズ、レコード境界、デバイス構成と版を検査する。
事前検証手段のない外部拡張モジュールを含む旧状態は、変更を始める前に拒否する。
旧形式全体を新しい安全な形式へ置き換える変更ではない。特にディスクのフォーマット処理途中には
旧FDC状態にネイティブポインターが含まれる問題が残っており、任意の途中状態の別プロセス復元は保証しない。
